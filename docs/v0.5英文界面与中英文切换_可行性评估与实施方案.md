## 0. 结论摘要（先看）

- **可行性：高。** 本项目是经典脚本 + 全局命名空间的纯前端单页应用（无构建链、无框架），i18n 改造即"字符串字典 + 渲染函数"模式，业界成熟，无技术未知项。
- **语言包形态（v2 核心变更）**：每种语言一个**独立数据文件** `js/i18n/<code>.js`（zh.js / en.js，未来 ru.js…），机制与数据彻底分离——i18n.js 只含渲染机制，**术语/文案全部在语言包内编辑**；新增语言无需改任何机制代码。
- **规模量化：** 用户可见中文文案约 **5,800+ 字符、分布在 12 个源文件中的 11 个**（js 10 个 + index.html，css 仅 1 处注释无影响），粗估 **约 150–170 条独立词条**。属于中等规模一次性收口改造，2–3 个工作批次可完成。
- **主要风险不在翻译本身，而在契约红线**：①M2N 输出 723 文件 hash 基线（backups/preR21h_723_output_hashes.json）要求输出文件**字节不变**；②告警文案是"行为契约"的一部分（AGENTS.md 明示"告警序列逐字保持"）；③UI 纪律（显隐必须显式值、setDirection 文本节点替换保留徽标）。
- **关键决策点（需用户批复，见 §8）**：转换后输出文件（.maa/.nec 内容）中的告警/注释**是否需要跟随界面语言**。本方案推荐 **方案 B1（输出文件固定英文，仅 UI 跟随语言）**——保告警契约可预期、且输出文件本就强制纯 ASCII。

## 2. 技术方案

### 2.1 架构（v2）：机制/数据分离 —— 独立语言包文件 + 全局注册表

```
js/i18n.js            # 机制（无任何文案）: L()/LF()/applyI18n()/setLang()/语言注册表读取
js/i18n/
  ├── zh.js           # 中文语言包（纯数据; 项目源语言, 键集最全的基准）
  ├── en.js           # 英文语言包（纯数据）
  └── (ru.js …)       # 未来语言: 复制 en.js 改码翻译即可, 机制零改动
js/state.js           # N2M.state 增加 lang: 'zh'（默认中文，契约现状）
index.html            # 静态文案节点加 data-i18n 属性 + 语言下拉框 + 两个语言包 script 引入
其余 js 文件           # 中文文案字面量 → L('key') 查表调用（含参数插值）
```

**为什么语言包是 .js 数据文件而非 .json（重要约束说明）**：本项目红线是 file:// 协议双击即用（无本地服务器、无构建链）。浏览器在 file:// 下禁止 `fetch`/XHR 读本地 JSON（Chrome 安全策略），而经典 `<script src>` 加载不受限。因此语言包采用**可执行 JS 文件、内容纯数据**的形态：手工编辑体验与 JSON 相当（对象字面量、支持 `//` 注释与尾逗号，比 JSON 更适合人写），加载用现有 script 链路，零新依赖。代价：语言包是被页面执行的代码（信任边界说明见 §6 R-i18n-10）。

**语言包文件规范（每个文件顶部固定注释模板 + 单一赋值）：**

```js
// js/i18n/en.js — English language pack (数据文件, 无逻辑)
// 编辑: 直接修改本文件, 保存后浏览器 Ctrl+F5 强刷生效; 键集须与 zh.js 对齐 (node tests/i18n_lang.js 自检)
// 段落: meta(语言元信息) / terms(术语表) / ui(界面文案) / warn(告警提示)
window.N2M_LANG = window.N2M_LANG || {};        // 注册表: 先建后挂, 任意顺序加载安全
window.N2M_LANG.en = {
    meta:  { code: 'en', name: 'English', htmlLang: 'en' },
    terms: {          // —— 术语表: 单词级, 供直接标签与句子引用 ——
        wire: 'wire', segment: 'segment', segmentation: 'segmentation',
        source: 'source', load: 'load', feedPoint: 'feed point',
        groundReal: 'real ground', groundPerfect: 'perfect ground', freeSpace: 'free space',
        conductivity: 'conductivity', permittivity: 'permittivity (εr)',
        taperedElement: 'tapered element', rearLobe: 'rear lobe (F/B)'
        // …约 25–35 条
    },
    ui: {             // —— 界面: 静态标签(data-i18n) + 动态文案(alert 等) ——
        'title.main': 'Antenna Model Format Converter',
        'ui.freq.label': 'Frequency (MHz)',
        'ui.btn.upload.nec': '📁 Import .nec'
        // …约 100 条
    },
    warn: {           // —— 告警: 完整句子, {参数} 插值, 可用 {{terms.x}} 引用术语 ——
        'warn.freq.empty': '❗ Frequency is required! The source file may lack an FR card; enter frequency (MHz) manually.',
        'warn.tag.range': '[Error] Tag {tag}: specified segment ({segIdx}) exceeds total segments ({ns})! Clamped to last segment (e).'
        // …约 60 条
    }
};
```

**机制要点（i18n.js，约 150–200 行，无文案）：**
- **注册表自发现**：可用语言 = `Object.keys(window.N2M_LANG)`（由已加载的语言包自动挂载）——语言下拉框据此动态生成，**未来加语言不触碰 i18n.js**。
- `L(key, params)`：按 `N2M.state.lang` 解析；**回退链：当前语言 → en → zh**（zh 为基准键集，保证任何键最终可解析）——未翻译完的新语言包也能直接运行，缺键逐条 console.warn，界面不崩溃。
- **术语引用语法 `{{terms.x}}`**：句子内可写 `Exceeds total {{terms.segment}}s ({ns}).`，L() 渲染时先递归展开 terms 引用再插值——**术语改一处、全语言内所有引用句同步**（"方便地独立编辑术语"的核心机制）。也允许直接写全单词（不强制引用）。
- `LF(key, params)`：**固定英文**解析（恒从 en 语言包取值，不看 state.lang）——专供 B1 方案下"写入输出文件"的文案（见 §2.5），与屏显 `L()` 同键不同视图。
- 插值：`{name}` 占位符，`str.replace(/\{(\w+)\}/g, …)`，与现有模板字面量语义一一对应。
- `applyI18n()`：全量刷新 `[data-i18n]`（文本）/`[data-i18n-ph]`（placeholder）；workTitle 特判走 firstChild 文本节点（R21j 徽标纪律）；select 的 option 仅改 textContent 保 value 不变。
- `setLang(code)`：写 state + localStorage（try/catch 回退内存态）→ 同步 `<html lang>`（取 meta.htmlLang）→ applyI18n() 全量刷新。
- 加载顺序：state → i18n.js → i18n/zh.js → i18n/en.js → utils → geometry → extract → maa2nec → convert → app（语言包无任何依赖、任意顺序加载安全，仅需在 app.js 的 DOMContentLoaded 前就位）。

**新增一种语言的完整步骤（面向未来扩展，机制零改动）：**
1. 复制 `js/i18n/en.js` → `js/i18n/<code>.js`，改 `meta`（code/name/htmlLang）+ 逐条翻译（terms/ui/warn；翻译不全也可用，缺键自动回退英文）；
2. index.html 语言包 script 区加一行 `<script src="js/i18n/<code>.js"></script>`；
3. 完成。下拉框自动出现新语言；`node tests/i18n_lang.js` 自动纳入新文件做键集/引用校验。

**语言包编辑工作流（用户视角）：**
- 用任意 UTF-8 文本编辑器直接改 `js/i18n/zh.js` / `en.js`（或未来语言包）；保存后浏览器 **Ctrl+F5** 强刷（避开 script 缓存）即生效；
- 改术语：只动 `terms` 段 + 检查 `ui` 段中的直接引用句；句子内的 `{{terms.x}}` 引用处自动同步；
- 改完跑 `node tests/i18n_lang.js`：键集对齐 / 插值占位符完整 / terms 引用有效 三项自动自检。

### 2.2 三类文案的处理策略

**A 类静态 UI（index.html）**
节点加 `data-i18n="key"`（文本）、`data-i18n-ph="key"`（placeholder）、`data-i18n-title`（如需要）。`applyI18n(root)` 启动 + 切换时全量刷新：
```js
document.querySelectorAll('[data-i18n]').forEach(el => el.textContent = L(el.dataset.i18n));
document.querySelectorAll('[data-i18n-ph]').forEach(el => el.placeholder = L(el.dataset.i18nPh));
```
注意 workTitle 的文本节点替换纪律（R21j：只改 firstChild 保留徽标 span）——applyI18n 对 workTitle 特判，仍走 `wt.firstChild.textContent` 路径。

**B 类动态 UI（app.js）**
`alert("请先载入 NEC 代码！")` → `alert(L('ui.alert.loadNecFirst'))`。逐条机械替换，不改逻辑。

**C/D 类转换告警（extract/convert/geometry/utils/parser/taper/writer）**
这是本方案的**核心分叉点**——告警文案具有"屏幕显示 + 写入输出文件"双重身份，见 §2.5 决策。

### 2.3 语言切换交互（v2：下拉框，天然支持多语言）

- **形态：语言下拉框**（小型 `<select>`，非 zh/en 二元 toggle——为未来 ru 等语言预留，避免届时重做控件）。选项 = 各语言包 `meta.name`（中文 / English / Русский…），由 i18n.js 启动时从注册表动态生成。
- 位置：**向导开屏右上角 + 工作区顶栏（btnSwitchDir 同行）各一个**，两控件同一事件源。
- 切换动作：`setLang(code)` → state → localStorage → `<html lang>` → applyI18n() 全量刷新 + 动态生成文案（select option、预设下拉、m2nAutoSegNote 常显提示）重渲染。
- 默认语言 zh（契约现状）；上次选择经 localStorage 恢复。

### 2.4 中英文字体与排版

- 现有字体栈 `-apple-system, "Segoe UI", …` 中英文均正常渲染，**css 无需改动**（唯一中文是注释）。
- 英文文案普遍长于中文 20–40%，标签栏/按钮需预留宽度。现有 CSS 布局以 flex/grid 自适应为主，仅 `.btn-mini`（按文件名/按原文件备注）与 settings-title 需实测确认不溢出；若有溢出在 css 微调（允许，因 css 唯一中文是注释，不涉契约）。

### 2.5 输出文件语言策略（三案对比 → 推荐 B1）

| 方案 | 屏显告警 | 输出文件 Warnings/CM 摘要 | 对 hash 基线影响 | 维护成本 |
|---|---|---|---|---|
| A：全跟随语言 | 跟随 | 跟随（中文模式输出中文 Warnings） | **破坏 .maa Warnings 行字节**；.nec 因 ASCII 终检**无法**输出中文 → 两方向行为不对称 | 高且丑 |
| **B1：UI 跟随，输出固定英文（推荐）** | 跟随 | 恒英文（LF() 从 en 语言包取） | .maa Warnings 恒为英文 = 与现状中文不同 → **hash 基线仍破坏一次**（见 R-i18n-4 处置） | 中 |
| B2：UI 跟随，输出维持现状中文 | 跟随 | 恒中文（.nec 侧的 warnings 不写入文件，仅屏显） | hash 零破坏 | 低 |

**推荐 B1**，理由：
1. 输出文件受众是软件（MMANA/4NEC2）与可能的外国用户，英文更通用；NEC 生态注释本就是英文惯例；
2. .nec 方向因 ASCII 终检**结构性地不能**跟随中文，B1 让两方向输出统一为英文，行为对称、可预期；
3. hash 基线只需**一次性重审定**（v0.5 新基线），且 R21 测试对告警文案的断言（r21 断言同步）在同批次更新——工程规则第 4 条已预留此流程："任何输出格式变化须重新审定基线"。

**B1 实现要点（v2 补充）**：C 类告警"一文案两视图"——warnings 数组内容由"中文字符串"改为**结构化条目 `{key, params}`**，在两个出口分别渲染：屏显 `L(key, params)`（跟随界面语言，含编号+空行排版 R21h 契约），写入文件 `LF(key, params)`（恒英文）。zh 基准语言包的对应键值与现中文文案**逐字一致**（翻译防回归工艺见 R-i18n-8）。

若用户更在意"零输出变化"，选 B2：告警写文件的部分（.maa Warnings 区）保持中文原句，屏显部分跟随语言——此时写入文件的文案不走 L()。**B2 是最低风险选项，B1 是更整洁的长期选项，二选一需批复。**

## 5. 英文翻译质量约定

- **术语表以语言包 `terms` 段为唯一权威来源**（v2：即 §2.1 示例中 terms 区），中英对照集中一处维护、句子经 `{{terms.x}}` 引用保持一致：
  | terms 键 | 中文 | 英文 |
  |---|---|---|
  | wire | 导线 | wire |
  | segment | 段/分段 | segment / segmentation |
  | taperedElement | 锥度振子 | tapered element |
  | feedPoint | 馈电点 | feed point |
  | source | 激励源 | source |
  | load | 负载 | load |
  | groundReal / groundPerfect / freeSpace | 真实地面/理想地面/自由空间 | real / perfect ground / free space |
  | conductivity / permittivity | 电导率/介电常数 | conductivity / permittivity (εr) |
  | addHeight | 附加高度 | additional height |
  | rearLobe | 后瓣 | rear lobe (F/B) |
  | forceSeg | 强制分段 | forced segmentation |
- 告警前缀：`[提示]/[警告]/[错误]` ↔ `[Info]/[Warning]/[Error]`（入 terms 段，全部告警句引用）。
- 单位与数值格式不动（Ω、MHz、mS/m、εr、° 原样保留）。
- 英文告警句式模板：`<severity> <what>: <detail> — <action required>.`
- 专有名词 MMANA-GAL / 4NEC2 / Sommerfeld-Norton / MININEC / GW/EX/LD/GN/FR 卡名不译。
